# QDS 因子研究模块 — 需求规格

## 定位

因子研究是量化研发链路的第一环。补上这块，平台就是完整的 **研究 → 回测 → 实盘** 闭环。

```
因子研究 (本模块)           →  策略开发  →  回测验证  →  实盘部署
┌────────────────────────┐
│ 阶段1: 因子探索 (秒级)   │     ↑已有       ↑已有       ↑已有
│ 阶段2: 信号诊断报告 (分钟) │
└────────────────────────┘
```

---

## 核心架构决策

### 向量化计算，不走 NT

NT 是事件驱动回测引擎，强项是模拟执行（滑点、手续费、订单簿）。因子研究需要的是**批量统计分析**：在 100 万根 bar 上算 IC、跑 shuffle test、扫参数热力图。这些必须用 **numpy/pandas 向量化计算**，不经过 NT。

```
数据层 (已有)                    计算层 (新增)                   展示层 (新增)
~/.tino/data/catalog/     →    src/tinohelm/research/     →    前端 /research 页面
Parquet (1m bars, ticks)        纯 pandas/numpy/scipy           读 JSON 渲染图表
                                不依赖 NautilusTrader
```

### 两阶段工作流

| | 阶段 1: 因子探索 | 阶段 2: 信号诊断报告 |
|---|---|---|
| **目的** | 快速筛选，淘汰 90% 的烂因子 | 深度验证，确认因子可用 |
| **速度** | 秒级（单因子单品种 IC） | 分钟级（shuffle test、跨品种、参数扫描） |
| **计算方式** | API 同步返回 | 异步 Job（Redis 队列，复用现有模式） |
| **交互** | 选因子 → 调参 → 即时看图 | 提交验证 → 等完成 → 看报告 |
| **结果** | 因子值不值得深入研究 | 因子能不能上线交易 |
| **前端** | 因子探索页（交互式） | 信号诊断报告页（4 Tab 报告） |

### 数据流

```
用户在 UI 选因子+品种+参数
        │
        ├─ [快速探索] POST /api/research/explore  (同步, <5s)
        │      → 加载 Parquet → 算因子 → 基础 IC/分层 → 返回 JSON
        │      → 前端即时渲染图表
        │
        └─ [深度诊断] POST /api/research/diagnose  (异步 Job)
               → 创建 ResearchJob → Redis 队列
               → Worker: 算因子 → IC 全套 → shuffle test → 跨品种 → 参数扫描
               → 结果写入 ~/.tino/data/research/{job_id}.json + DB 记录
               → 完成后弹 toast (Layer 3)
               → 前端 /research/report/{job_id} 渲染报告
```

## 计算引擎 (`src/tinohelm/research/`)

### 模块结构

```
src/tinohelm/research/
├── __init__.py
├── loader.py          # Parquet → pandas DataFrame（复用 catalog 路径规范）
├── factors.py         # 内置因子库：每个因子是一个 compute(df, params) → Series
├── registry.py        # 因子注册表：扫描内置 + ~/.tino/research/factors/ 自定义
├── analysis.py        # IC / 衰减 / 分层收益 / 分布统计 / 换手率
├── robustness.py      # Shuffle test / 分段稳定性 / 跨品种
├── cost.py            # Gross→Net edge waterfall / 手续费损耗
├── param_scan.py      # 单参数 sweep + 双参数 heatmap
├── report.py          # 汇总所有分析 → 标准 JSON 结构
└── worker.py          # 异步 Job consumer（同 data/worker.py 模式）
```

### 内置因子库 (`factors.py`)

每个因子签名统一: `compute(df: DataFrame, params: dict) → Series`

| 类别 | 因子 ID | 公式概要 | 参数 | 需要数据 |
|------|---------|----------|------|----------|
| **动量** | `ret_N` | `close.pct_change(N)` | lookback | bar |
| | `mom_ratio` | `SMA(fast) / SMA(slow) - 1` | fast, slow | bar |
| | `roc` | `close / close.shift(N) - 1` | lookback | bar |
| | `rsi_signal` | `RSI(N) - 50` (居中化) | lookback | bar |
| **波动** | `realized_vol` | `ret.rolling(N).std()` | lookback | bar |
| | `vol_ratio` | `ret.rolling(fast).std() / ret.rolling(slow).std()` | fast, slow | bar |
| | `atr_norm` | `ATR(N) / close` | lookback | bar |
| | `parkinson_vol` | `sqrt(1/4ln2 * (ln(H/L))^2)` rolling | lookback | bar |
| **量价** | `vwap_dev` | `(close - VWAP(N)) / close` | lookback | bar |
| | `volume_surge` | `volume / volume.rolling(N).mean()` | lookback | bar |
| | `obv_slope` | `OBV.diff(N) / N` | lookback | bar |
| **微观** | `trade_imbalance` | `(buy_vol - sell_vol) / total_vol` | window | trade_tick |
| | `kyle_lambda` | `Δprice / Δvolume` 回归系数 | window | trade_tick |
| | `amihud_illiq` | `|ret| / volume` rolling | lookback | bar |

#### Tab 1 — Signal Profile（信号特征）

验证因子本身的统计性质：分布合理吗？有没有病态？

##### 指标卡片行

```
┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
│  均值     │ │  标准差   │ │  偏度     │ │ lag-1 ACF│ │ 与RV相关  │ │ 零值占比  │
│  0.021   │ │  0.142   │ │  -0.31   │ │  0.87    │ │  0.34    │ │  2.1%    │
└──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘
```

| 指标 | 说明 | 合格标准 |
|------|------|----------|
| 均值 | 因子均值 | 不应偏离 0 太远（除非设计如此） |
| 标准差 | 因子波动 | 不应为 0（无变化 = 无用因子） |
| 偏度 | 分布对称性 | \|skew\| < 3 |
| lag-1 ACF | 自相关 | 太高(>0.99)说明几乎不变，太低(<0.1)说明纯噪声 |
| 与 RV 相关 | 和已实现波动率的相关性 | 如果太高，可能只是在看波动，不是独立 alpha |
| 零值占比 | 因子值为 0 的比例 | < 30%，太高说明信号太稀疏 |

##### Signal Profile 的 Pass/Fail 规则

| 条件 | 状态 |
|------|------|
| std = 0 或零值 > 50% | ✗ FAIL |
| \|skew\| > 5 或 ACF > 0.999 | ⚠ WARN |
| 其他 | ✓ PASS |

## 自定义因子

### 文件规范

放在 `~/.tino/research/factors/*.py`，平台自动发现。

```python
# ~/.tino/research/factors/my_momentum.py

FACTOR_META = {
    "name": "my_momentum",
    "label": "自定义动量",
    "category": "自定义",
    "data_type": "bar",
    "params": {
        "fast": {"default": 5, "min": 1, "max": 100, "label": "快线周期"},
        "slow": {"default": 20, "min": 5, "max": 500, "label": "慢线周期"},
    },
}

def compute(df, params):
    """输入 DataFrame (OHLCV)，输出 Series (因子值)。"""
    fast_ma = df["close"].rolling(params["fast"]).mean()
    slow_ma = df["close"].rolling(params["slow"]).mean()
    return (fast_ma / slow_ma) - 1
```

### 导入流程

1. `+ 导入因子` 按钮 → 显示路径提示 `~/.tino/research/factors/`
2. 平台验证（有 `FACTOR_META` + `compute`）
3. 通过 → 出现在因子列表"自定义"组
4. 失败 → InlineError 说明原因

## 设计约束

- 遵循 QDS Warm 设计系统，复用所有 token/颜色/字体/间距
- 图表用 Recharts，复用 `chartTheme.ts`（tooltip、grid、axis 风格一致）
- 热力图可能需要额外图表库（Recharts 无原生 heatmap），备选：自定义 SVG 或 `nivo`
- 左侧配置面板参考 data-catalog FetchDialog 表单风格
- 报告页卡片参考 backtest detail 页布局
- 空状态参考 `qds-empty-states.html`
- Pass/Fail badge 用 StatusBadge 组件
- 评级星星 ★ 用 `--acc` 烧橙色
- IC 正值 `--suc` 绿，负值 `--dan` 红，零线 `--t3` 灰
- 分层颜色：Q1 绿 → 中间灰 → QN 红
- 热力图色阶：深绿 → 白 → 深红
- Waterfall chart：扣减项红色，净值绿/红取决于正负
